## Linux系统调用的过程

系统调用是用户态程序与操作系统内核进行交互的接口。为了保证系统的安全性，用户态程序缺乏足够的权限去直接操作底层的硬件或内核数据，必须通过系统调用的方式跨越特权级（从 Ring 3 到 Ring 0），请求内核代为执行。

Linux系统调用的执行过程随着架构和硬件演进而发生了很大的变化，主要可以分为**旧版（基于软中断）**和**新版（基于快速系统调用指令）**两种实现方式。

### 1. 触发系统调用的准备工作
无论是旧版还是新版，系统调用的前置动作基本一致：
1. **传递系统调用号**：由于所有的系统调用都会进入同一个统一的内核入口，系统必须知道用户想调用的是哪个具体的函数。这个标识被称为“系统调用号”，通常被放入特定的寄存器中（如 x86 体系下的 `eax`，或 x86_64 体系下的 `rax`）。
2. **传递参数**：系统调用所需的参数会按照 ABI (应用程序二进制接口) 约定，放入其他通用寄存器中（如 `ebx`, `ecx`, `edx` 或 `rdi`, `rsi`, `rdx` 等）。

---

### 2. 旧版实现：基于软中断（`int 0x80`）
在早期的 x86 架构（32位）系统中，系统调用主要是通过**软件中断**来实现的。

**深入执行过程：**
1. **触发中断**：用户态程序在准备好寄存器后，执行汇编指令 `int 0x80`。这会触发一个异常/中断（中断向量号为 128 / 0x80）。
2. **查表陷入内核**：CPU 收到中断信号后，硬件机制会暂停当前代码执行，**切换栈指针**（从用户栈切换到内核栈），并将当前的 `SS` (栈段寄存器)、`ESP` (栈指针)、`EFLAGS` (标志寄存器)、`CS` (代码段寄存器)、`EIP` (指令指针) **压入内核栈**以保存现场。
3. **定位处理程序**：通过查**硬件中的中断描述符表（IDT，Interrupt Descriptor Table）**，找到 0x80 对应的中断处理程序入口点（通常对应的内核汇编函数为 `system_call`）。
4. **分发系统调用**：内核在 `system_call` 流程中，根据保存的 `eax` 寄存器里的系统调用号，去 **系统调用表（`sys_call_table`）** 中索引真正的系统调用服务例程（例如 `sys_read` 等）并执行。
5. **恢复现场并返回**：系统调用例程执行完毕，将返回值存入 `eax` 寄存器。内核最后执行 `iret` (Interrupt Return) 指令，CPU 硬件将先前压入内核栈的 `EIP`、`CS` 等一系列寄存器内容弹回，在此过程中完成降级（特权级切回 Ring 3），并回到用户程序之前打断的地方继续运行。

> **缺点**：基于中断的机制非常繁杂。必须经过内存级的 IDT 查表、细致的特权级检查、以及大量硬件级的自动压栈操作，带来了高昂的 CPU 时钟周期开销（数百个时钟周期）。

---

### 3. 新版实现：基于快速系统调用（`sysenter` / `syscall`）
为了解决中断进入内核导致的开销过大问题，Intel 和 AMD 在后续的硬件层面直接引入了专属的“快速系统调用”汇编指令（32位通常引入了 `sysenter`/`sysexit`，64 位 x86_64 体系下，`syscall`/`sysret` 成为绝对的标准）。

**深入执行过程（以 x86_64 的 `syscall` 为例）：**
1. **执行专用指令**：用户程序准备好 `rax` (系统调用号) 以及其他寄存器后，直接执行 `syscall` 指令。
2. **基于 MSR 寄存器直接跳转**：CPU 硬件不再去内存中查 IDT 中断描述符表，而是直接从一组特殊硬件寄存器——**MSR（Model-Specific Registers，特定模型寄存器）**中读取事先记录好的内核入口地址。
   - CPU 自动将当前的指令指针（`RIP`）保存到 `RCX` 寄存器中，标志寄存器（`RFLAGS`）保存到 `R11` 寄存器中。
   - 直接将 `MSR_LSTAR` 寄存器中保存的内核处理程序地址（如 `entry_SYSCALL_64`）赋值给指令指针 `RIP`，并直接将 CPU 权限级别升级跳变到 Ring 0 特权态。
3. **轻量级上下文保存**：迅速进入内核代码后，由内核汇编去负责手工切换到内核栈，并使用 `push` 保存运行所必需的用户态通用寄存器。由于避开了硬件强制性的一整套压栈操作，操作系统此时有了更大的控制权和更高的保存效率。
4. **分发并执行**：依然是根据 `rax` 中的调用号，在 `sys_call_table` 内进行查表然后调用对应的核心态例程。
5. **快速返回**：内核例程处理完成且返回结果已写入 `rax`，清理内核栈后执行 `sysret` 指令。CPU 快速从 `RCX` 读回下一条用户态指令地址给 `RIP`，从 `R11` 恢复核心标志位，将态势平滑降维至 Ring 3 ，继续执行。

> **优点**：直接规避了笨重的内存 IDT 查表、去掉了大量不需要的自动权限检查与硬件压栈。通过专属硬件连线（寄存器间拷贝），将原本数百上千的时钟周期开销骤降到了几十个时钟周期，极大缩减了切换延迟。

---

### 4. 补充机制：vDSO (零切换系统调用)
既然哪怕用 `syscall` 这种快路进入内核依然会有上下文切换开销，现代 Linux 为了进一步提升性能，引入了极限优化手段 —— **vDSO (Virtual Dynamically Shared Object，虚拟动态共享对象)**：
- Linux 内核会将一小段实现纯读取、零特权安全风险的内核逻辑（例如 `gettimeofday` 获取高精度时间代码），编译成动态库直接被映射进入所有的用户进程地址内存空间。
- 当开发者在代码里调用 `gettimeofday` 这类系统函数时（通常经过 glibc 封装），进程是在**自己的用户态（Ring 3）**中直接读取这些被映射的内存页信息并处理的。
- 这意味着：**完全不执行中断指令、完全不需要越级陷入内核态、零特权级切换开销**，调用的运行速度等价于一次程序普通的函数调用。此外 glibc 层也会在这里自动对那些必须跨特权的调用（比如 IO 读写），进行 `int 0x80` 还是 `syscall` 的多态分发裁决。
