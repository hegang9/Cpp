## 返回值优化（RVO / NRVO）

### 概念

返回值优化（Return Value Optimization, RVO）是编译器在返回对象时进行的拷贝消除优化。它会直接在调用者的返回值缓冲区构造返回对象，避免临时对象的拷贝或移动。

- **RVO**：返回匿名临时对象时的拷贝消除。
- **NRVO**：返回具名局部对象时的拷贝消除。

### 触发条件（常见场景）

- 函数返回一个对象（值返回）。
- 返回对象类型与函数返回类型一致。
- 编译器能够确定返回的对象是唯一且可直接构造在调用者处。

### C++17 之后的变化

C++17 起，对于**返回临时对象**（prvalue）场景，拷贝消除是**强制保证**的。也就是说：

```cpp
T make();
T t = make();
```

在 C++17 起不再需要拷贝/移动构造，即使构造函数被标记为 `explicit` 或被删除，也不会阻止该优化。

### 可能无法优化的情况

- 返回多个不同对象（有分支导致返回不同局部变量）。
- 返回的对象类型与返回类型不同（需要类型转换）。
- 编译器无法确定唯一返回对象。
- 关闭了拷贝消除（如 GCC/Clang 使用 `-fno-elide-constructors`）。

### 示例：观察 RVO/NRVO

```cpp
#include <iostream>

struct Log {
	Log() { std::cout << "default\n"; }
	Log(const Log&) { std::cout << "copy\n"; }
	Log(Log&&) noexcept { std::cout << "move\n"; }
};

Log makeTemp() {
	return Log{}; // RVO
}

Log makeNamed() {
	Log obj;      // NRVO
	return obj;
}

int main() {
	Log a = makeTemp();
	Log b = makeNamed();
	return 0;
}
```

### 与移动语义的关系

如果 RVO/NRVO 不能生效，编译器会尝试使用**移动构造**替代拷贝构造。因此：

- 先尝试拷贝消除；
- 失败时，优先尝试移动构造；
- 再失败时，才会拷贝构造。

### 实践建议

- 优先按值返回对象，依赖 RVO/NRVO。
- 避免为了“手动优化”而返回 `std::move(local)`，这可能反而阻止 NRVO。
- 如需观察行为，可临时关闭拷贝消除进行对比。
