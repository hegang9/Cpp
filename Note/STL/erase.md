## erase函数详解

`erase` 是 C++ STL 容器中的核心成员函数，用于从容器中移除一个或多个元素。由于不同 STL 容器的底层数据结构完全不同，`erase` 的底层实现机制、时间复杂度以及对**迭代器失效（Iterator Invalidation）**的影响也有着天壤之别。

### 1. 序列式连续内存容器（`std::vector`, `std::deque`, `std::string`）
这些容器的元素在内存中是连续（或分块连续）排列的。

* **底层机制**：当调用 `erase(it)` 删除特定位置的元素时，为了填补删除后留出的内存空隙并保持连续性，底层必须调用赋值运算符（或移动赋值运算符），将该位置身后的**所有元素逐个向前移动一个位置**。最后，再调用尾部元素的析构函数销毁多余的对象，并更新容器内部的 `size` 计数器属性（容量 `capacity` 通常保持不变，除非调用 `shrink_to_fit`）。
* **时间复杂度**：与被删除元素后面的元素数量成正比，通常为 $O(N)$。在尾部删除是 $O(1)$。
* **迭代器失效规则**：由于其后的元素发生了集体位移，**指向被删除元素及其之后所有元素的迭代器、指针和引用都会失效**。
* **返回值**：`erase` 会返回一个指向**被删除元素之后的那个元素**的**有效迭代器**。即使对于 `vector` 来说它底层的指针地址可能和删除前一模一样，原有的迭代器也从语义上“失效”了。必须**直接使用或者接收**这个返回的新迭代器进行后续遍历或操作。

### 2. 节点式容器（`std::list`, `std::forward_list`）
底层实现为双向链表或单向链表。

* **底层机制**：在链表中删除一个节点，底层仅仅需要修改被删除节点前后相邻节点的指针（前驱和后继 `next` / `prev` 指针），将其从链式结构中“摘除”，然后直接 `delete` 释放被摘除节点的内存。不需要移动任何其他元素的数据。
* **时间复杂度**：寻找元素需要 $O(N)$，但如果已经给定了迭代器，则执行 `erase` 动作本身的时间复杂度是 $O(1)$。
* **迭代器失效规则**：**仅指向被删除元素的迭代器失效**，其他所有元素的迭代器保持有效，因为它们在内存中的绝对地址并未发生改变。
* **返回值**：返回被删除元素下一个节点的迭代器。

### 3. 关联式容器（`std::map`, `std::set`, `std::multimap` 等）
底层实现通常为**红黑树（Red-Black Tree）**。

* **底层机制**：从红黑树中剔除一个节点。如果该节点是叶子节点直接摘除；如果有子节点，则需要寻找其前驱或后继节点来替换它的位置。最关键的是，删除节点可能会破坏红黑树的平衡规则（例如连续红节点、黑高度改变等），因此底层会伴随一系列复杂的**左旋、右旋和颜色翻转**操作以恢复树的平衡。
* **时间复杂度**：由于涉及到树的遍历和可能触发的自底向上重平衡，时间复杂度为 $O(\log N)$。
* **迭代器失效规则**：与链表类似，各节点在内存中独立分配。因此，**仅指向被删除元素的迭代器失效**，其他迭代器依然有效。
* **返回值（C++11起）**：返回一个指向被删除元素**之后**一个元素的新迭代器（如果删除的是最后一个元素，则返回 `end()`）。
  * *注：在 C++98 标准中，`std::map / std::set` 的 `erase(iterator)` 返回类型是 `void`。从 C++11 开始，标准将它们统一修改为返回下一个元素的迭代器，从而可以像 `vector` 和 `list` 一样方便地在循环中使用 `it = m.erase(it);`*。

### 4. 无序关联式容器（`std::unordered_map`, `std::unordered_set` 等）
底层实现为**哈希表（Hash Table，通常是数组 + 链表/红黑树 的拉链法实现）**。

* **底层机制**：根据所存元素的 Hash 值定位到桶（Bucket），在此桶所维护的链表（或树）中遍历找到该元素，并执行类似于单链表节点删除的摘除操作，然后释放内存。
* **时间复杂度**：平均情况下是 $O(1)$。最坏情况（严重哈希冲突导致链表很长）下为 $O(N)$。
* **迭代器失效规则**：仅指向被删除元素的迭代器失效。普通的 `erase` 操作不会改变桶的数量，所以不会引发 `rehash`，其他迭代器仍然有效。
* **返回值**：与 C++11 后的有序关联容器一样，返回被删除元素之后的那个有效的迭代器。

### 5. 高频考点：如何在循环中安全地使用 erase 删除元素？
由于 `erase` 会导致迭代器失效，如果直接在 `for` 或 `while` 循环中 `erase` 再执行 `it++`，会导致未定义行为（通常是越界崩溃）。

**正确写法（C++11 之后标准化）：利用 `erase` 的返回值**
几乎所有容器的 `erase` 返回的都是被删除元素的**下一个有效元素的迭代器**。
```cpp
// 以 vector 为例（map、list 等完全通用）
std::vector<int> vec = {1, 2, 3, 4, 5};
for (auto it = vec.begin(); it != vec.end(); ) {
    if (*it % 2 == 0) {
        // 删除偶数，it 被更新为下一个元素的有效迭代器，不需要手动 it++
        it = vec.erase(it);
    } else {
        // 只有不删除时，才手动前进到下一个节点
        ++it;
    }
}
```

### 6. C++20的改进：统一擦除非成员函数
在 C++20 之前，要在 `vector` 中删除所有特定值的元素，必须使用晦涩的所谓 `Erase-Remove` 惯用法：
```cpp
// C++11/14/17 做法（Erase-Remove Idiom）
vec.erase(std::remove(vec.begin(), vec.end(), target_value), vec.end());
```
为了简化这种底层位移操作带来的一连串样板代码，**C++20** 引入了非成员函数 `std::erase` 和 `std::erase_if`：
```cpp
// C++20 做法：极其简洁，且内部已做到最优的批量向前移动（避免多次 O(N) 移动）
std::erase(vec, target_value);          // 删除所有等于 target_value 的元素
std::erase_if(vec, [](int x){ return x % 2 == 0; }); // 删除所有偶数
```
