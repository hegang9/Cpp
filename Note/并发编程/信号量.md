## 信号量
线程同步的一种机制，允许多个线程访问共享资源，但限制同时访问的线程数量。信号量维护一个计数器，表示可用资源的数量。当线程请求资源时，计数器减1；当线程释放资源时，计数器加1。如果计数器为0，表示没有可用资源，请求线程将被阻塞，直到有资源可用。

### 底层实现
信号量的底层实现通常依赖于操作系统提供的原语，如互斥锁（mutex）和条件变量（condition variable）。在 Linux 中，信号量可以通过 `sem_t` 结构体和相关函数（如 `sem_init`, `sem_wait`, `sem_post`）来实现。这些函数内部可能使用 Futex（Fast Userspace Mutex）机制来优化性能，允许在用户态进行快速的资源获取和释放，只有在竞争激烈时才进入内核态进行阻塞和唤醒操作。

#### 现代操作系统的底层实现（以 Linux Futex 为例）
在现代操作系统（如 Linux）中，为了极大地提高并发性能，避免频繁地陷入内核态，信号量的底层实现通常基于 **原子操作（Atomic Operations）** 与 **Futex（Fast Userspace Mutex）机制**。它的核心思想是：**无竞争的情境下在用户态直接完成，只有发生竞争需要阻塞时才陷入内核态。**

其核心不再依赖传统笨重的互斥锁，而是直接依赖一个基于原子的整型状态变量：

**1. P 操作 (Wait / `sem_wait`)：申请资源**
- **用户态快路径（Fast Path）**：利用硬件提供的 CAS（Compare-And-Swap）或原子递减指令尝试将计数器减 1。如果获取前计数器大于 0，说明成功获取到资源，直接返回，**全程停留在用户态**。
- **内核态慢路径（Slow Path）**：如果当前资源数为 0，说明没有可用资源，线程必须挂起等待。此时才通过系统调用 `futex(addr, FUTEX_WAIT, ...)` 将当前线程挂入内核级的等待队列中，陷入睡眠。

```cpp
void sem_wait(sem_t *sem) {
    // 尝试在用户态通过原子操作获取资源 (Fast Path)
    while (true) {
        int val = atomic_load(&sem->count);
        if (val > 0) {
            // 原子的比较和交换：期望当前值是val，并将其更新为 val - 1
            if (atomic_compare_exchange(&sem->count, &val, val - 1)) {
                return; // 获取成功，直接返回
            }
        } else {
            // 资源不够 (val == 0)，只能走 Slow Path
            // 调用系统调用 futex 进行阻塞，休眠直到 sem->count 的值发生改变
            futex_wait(&sem->count, 0); 
        }
    }
}
```

**2. V 操作 (Signal / `sem_post`)：释放资源**
- **用户态快路径（Fast Path）**：通过原子操作直接将计数器加 1。
- **陷入内核唤醒（WAKE）**：加 1 后，如果确认有其他线程正在阻塞等待该资源（现代实现中一般会附带一个 `waiters` 计数或通过复用最高位表示是否有等待者），则通过系统调用 `futex(addr, FUTEX_WAKE, 1)` 陷入内核态，唤醒 1 个（或多个）阻塞的挂起线程。

```cpp
void sem_post(sem_t *sem) {
    // 在用户态原子加 1 归还资源
    atomic_fetch_add(&sem->count, 1);
    
    // 检查是否有线程由于资源不足而正在等待阻塞（glibc实现会对此进行优化判断）
    if (has_waiters(sem)) {
        // 陷入内核态，唤醒一个等待线程
        futex_wake(&sem->count, 1); 
    }
}
```

**为什么现代系统这样设计？**
早期的核心设计（基于禁用中断或操作系统级无条件加锁）在每次 P/V 操作时都需要切换到内核态，开销巨大。而现代应用中，绝大多数并发执行路径都处于**无大量竞争**的状态。因此引入 **Futex** 的双层结构：
- 取资源无需等待的情况下，只需要几条低开销的用户级汇编 CPU 指令（原子 CAS 即可）；
- 当真正遇到资源枯竭时，再把耗时的阻塞/唤醒工作交给内核调度器管理。这种软硬结合的方式实现了性能的飞跃。
