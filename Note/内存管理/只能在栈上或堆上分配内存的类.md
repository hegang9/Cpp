## 只能在堆上分配的类
将构造和析构私有，提供静态成员函数创建对象，返回指针，析构函数在静态成员函数中调用
```cpp
class MyClass {
private:
    MyClass();  // 私有构造函数
    ~MyClass(); // 私有析构函数

public:
    static MyClass* create();  // 静态成员函数创建对象
    void destroy();            // 静态成员函数销毁对象
};
```

## 只能在栈上分配的类
要限制对象只能在栈上分配，需要禁止通过 `new` 操作符在堆上分配内存。
这可以通过将 `operator new` 和 `operator delete` 函数设为私有访问权限来实现。在 C++11 及以后的版本中，更推荐的做法是使用 `= delete` 显式禁用它们。

```cpp
class StackOnly {
public:
    StackOnly() {}
    ~StackOnly() {}

private:
    // C++11: 禁用 new 和 delete 操作符以防止堆分配
    void* operator new(size_t size) = delete;
    void operator delete(void* ptr) = delete;
    
    // 如果需要，也可以禁用数组形式的 new[] 和 delete[]
    void* operator new[](size_t size) = delete;
    void operator delete[](void* ptr) = delete;
};
```

**注意事项**：
这种方法仅仅是禁用了 `new StackOnly` 这样的直接堆内存分配。然而，它并不能阻止该类的对象作为另一个类的成员，而那个外层类对象如果在堆上分配，那么这个“只能在栈上分配”的对象实际上还是间接存在于堆内存中了。

**能否禁止间接分配？**
在 C++ 标准中，**没有任何完美的编译期方案**能彻底防止一个类作为其他类的成员被间接分配在堆上。
1. **运行时检查（非标准 Hack）**：可以在构造函数中获取一个局部变量（必定在栈上）的地址，并与 `this` 指针比较，判断 `this` 是否位于当前线程的栈空间范围内（通常通过操作系统 API 或假设栈地址连续）。但这严重依赖底层平台、移植性极差，且有运行时开销，非常不推荐。
2. **工程实践角度**：C++ 的核心理念是“防误用而不防恶意滥用”（preventing accidental misuse, not intentional abuse）。通过显式禁用 `new` 和 `delete` 操作符，已经向其他开发者传达了极其明确的“仅限本地局部对象”的语义约束。对于强行将其包装进其他堆对象的行为，通常依靠团队的开发规范和代码审查（Code Review）来防范即可。
