## 内存池优化内存使用的原理
内存池预先分配一大块内存，并将其划分为多个固定大小的内存块。当需要分配内存时，直接从内存池中取出内存块，而不是每次都调用操作系统的内存分配函数。
减少了内存碎片，提高了内存分配和释放的效率，尤其适用于频繁分配和释放小块内存的场景。

## 内存映射 (Memory Mapping)

### 1. 内存映射文件是什么？
内存映射文件（例如 Linux 环境下的 `mmap`）是一种将磁盘上的文件内容直接映射到进程的虚拟地址空间的技术。
映射建立后，进程可以像访问普通内存数组一样直接通过指针读写文件，而不需要显式地调用 `read()` 或 `write()` 等传统的系统调用。

**主要机制与优势：**
- **减少内存拷贝次数（零拷贝思想部分体现）**：传统的文件读写过程需要将数据从磁盘加载到内核缓冲（Page Cache），再从内核缓冲拷贝到用户空间的 Buffer。内存映射直接将用户空间的虚拟地址映射到内核的 Page Cache 上，避开了“内核态到用户态”的这一次数据拷贝，性能大幅提升。
- **按需加载（懒加载与缺页中断）**：映射时操作系统**并不会立刻把整个大文件全部搬进物理内存**，而仅仅是分配了一段虚拟地址空间。当程序真正通过指针访问某个地址段时，会触发**缺页中断（Page Fault）**，操作系统才会去磁盘中把对应位置的数据页加载到物理内存中。

### 2. 内存映射与流式读写的性能差异原因
#### 流式读写：
- 数据路径： 磁盘 →→ （DMA拷贝） →→ 内核态缓冲区（Page Cache） →→ （CPU拷贝） →→ 用户态缓冲区（你的 char buffer[]）
- 瓶颈点：存在两次数据拷贝，第一次拷贝由DMA完成，不是瓶颈，但第二次拷贝是CPU完成的，且涉及用户态和内核态的切换，开销较大。
#### 内存映射：
- 数据路径： 磁盘 →→ （DMA拷贝） →→ 内核态缓冲区（Page Cache） →→ 用户态虚拟地址空间（直接访问）
- 改进点：没有了第二次CPU拷贝，且访问文件数据就像访问内存一样，极大提升了性能。

#### 内存映射的缺页中断开销：
缺页中断会带来一定的性能开销，因为每次访问未加载到物理内存的数据页时，操作系统都需要进行页面调度和数据加载操作。但在大多数情况下，这种开销远小于传统文件读写的两次内存拷贝开销。而流式读写有成熟的内核预取机制，可以在访问数据之前就预先加载数据页，减少缺页中断的发生频率。但整体来说，内存映射在处理大文件时通常表现更好，尤其是当访问模式具有局部性（即访问的数据集中在文件的某些区域）时。

### 3. 如何用它来处理大文件？

当面对几十 GB 甚至更大的文件时，如果用传统的 `read` 全部读入内存会直接导致 OOM (Out Of Memory)。内存映射提供了优雅的解决方案：

1. **整体映射（依赖 OS 的页面置换算法）**：
   在 64 位操作系统下，进程有庞大的虚拟地址空间。你可以直接将 10GB 的文件“整体映射”。你可以把它当成一个巨大的 10GB 数组直接操作。至于物理内存（比如只有 4GB）不够用的问题完全交给 OS 解决：操作系统的内存管理器会运用 LRU 等置换算法，自动将当前正在访问的数据页载入物理内存，并将长时间不访问的数据页淘汰（或刷写回磁盘），开发者完全免去了自己维护缓冲区指针和滑动的麻烦。

2. **滑动窗口映射（分块映射）**：
   在资源受限或依然是 32 位系统的环境下（虚拟内存空间有限），可以采用滑动窗口映射：每次只调用 `mmap` 映射文件的部分内容（例如偏移量从 0 开始映射 100MB），处理完这 100MB 后，调用 `munmap` 解除映射，再将偏移量向后移动，映射下一个 100MB 的“窗口”，直到文件处理结束。

### 4. Linux 下的简单使用示例 (C++)
```cpp
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <iostream>

int main() {
    const char* filepath = "large_file.bin";
    // 1. 打开文件
    int fd = open(filepath, O_RDONLY);
    size_t length = 1024 * 1024 * 1024; // 假设处理 1GB 的文件

    // 2. 建立内存映射
    // 参数含义：映射起始地址(NULL由OS决定)、长度、保护标志(只读)、映射类型(共享)、文件描述符、文件偏移量
    char* mapped_data = (char*)mmap(NULL, length, PROT_READ, MAP_SHARED, fd, 0);

    if (mapped_data == MAP_FAILED) {
        std::cerr << "mmap failed!" << std::endl;
        close(fd);
        return -1;
    }

    // 3. 如同操作普通内存一样访问文件（此时发生按需加载/缺页中断）
    for (size_t i = 0; i < length; i += 4096) { // 按页步进处理
        char c = mapped_data[i]; 
        // ... 进行数据统计或处理逻辑
    }

    // 4. 解除映射并清理资源
    munmap(mapped_data, length);
    close(fd);
    return 0;
}
```

### 5. 内存映射常问八股：
1. 10GB 的文件，里面全是字符串，1GB内存，对文件中的字符串进行频率统计，找出频率最高的字符串。（大数据量，小内存约束题）
答：使用**哈希分治法**：
   - 大拆小：顺序读取10GB文件，这里可以直接使用fread或者mmap分块读取，每次处理1GB的数据块。对读到的每一个字符串计算哈希值，根据哈希值将字符串写入100个小文件中，这可以保证相同的字符串一定会被写入同一个小文件中。
   - 小文件统计：现在每个小文件都大概只有100MB（分布均匀的情况下），完全可以加载到内存中。对每个小文件进行频率统计（使用map），找出该小文件中频率最高的字符串和它的频率；如果哈希函数选的太烂，导致不同的字符串哈希冲突严重，一个小文件里有很多不同的字符串，导致map占用内存过大，这时可以继续对这个小文件进行二次哈希分治，直到每个小文件中的字符串数量足够少或者1GB的内存可以容纳下map，就可以直接统计。
   - 归并结果：比较这100个小文件中频率最高的字符串，找出全局频率最高的字符串。
