## 从底层开讲malloc内存分配机制
#### 进程的内存布局
当一个程序被操作系统加载执行时，它会得到一个专属于它的、独立的虚拟地址空间。在这个空间中，内存被划分为几个主要区域，它们从低地址到高地址依次是：
1. 代码段：存储代码
2. 数据段：包含.data（存放已初始化的全局变量和静态变量）和.bss（存放未初始化或初始化为0的全局变量和静态变量）
3. 堆：用于动态内存分配的区域，从低地址向高地址增长
4. 内存映射段：进程与外界进行高效内存交互的关键通道，可映射共享库、实现进程通信、进行文件映射（将文件映射到该区域，对这段内存的读写操作会由操作系统自动回写到对应的文件位置，避免了对文件进行频繁的系统调用），从高地址向低地址增长。
5. 栈：用于函数调用，存放局部变量、参数等，从高地址向低地址增长
6. 内核空间：存放操作系统内核代码和数据

#### 堆的分配单元
malloc并不是以字节为单位管理堆内存的，而是以一个称为 chunk（内存块）​的结构为基本单位。每一个 chunk 都由两部分组成：**元数据（也称为 chunk 头）​ 和 可用内存（用户数据区）**
- 元数据：包含以下两个字段
  - mchunk_prev_size：存储前一个相邻 chunk​ 的大小（如果前一个 chunk 是空闲的）
  - mchunk_size：存储当前 chunk​ 的总大小。这个字段的低几位被用作标志位，其中最重要的是 P (PREV_INUSE)位，它指示了前一个 chunk 是正在使用中（1）还是空闲（0）
- 可用内存区：这是 malloc返回给用户的指针真正指向的区域。一个精妙的设计在于，当 chunk 被分配给用户后，其元数据中原本用于空闲链表指针的空间（fd, bk等）可以被用户数据覆盖复用，以节省空间。

#### Bins管理机制
为提高内存分配和回收效率，malloc维护并管理一个**内存池**（这个内存池在堆上），核心的管理结构就是bins（垃圾桶）。当分配和回收内存时，优先考虑这个内存池。bins的实质就是一组不同特性的空闲内存块链表：
| Bin类型      | 管理方式     | 块大小         | 特点与用途                                                                                                   |
| ------------ | ------------ | -------------- | ------------------------------------------------------------------------------------------------------------ |
| Fast bins    | 单链表       | 小             | 高速缓存，不立即合并相邻空闲块，分配/释放极快                                                                |
| Unsorted bin | 双向循环链表 | 各种大小       | 中转站，刚被释放的块先暂存在这，后续可快速复用                                                               |
| Small bins   | 双向循环链表 | 小（固定大小） | 每个 bin 管理相同大小的 chunk，速度很快。当 unsorted bin 中的 chunk 不合适时，会按大小归类到 small bins      |
| Large bins   | 双向循环链表 | 大（范围大小） | 每个 bin 管理一个大小范围内的 chunk，链表中的 chunk 按大小排序，分配时需要查找最佳匹配，速度较慢但管理大内存 |

#### malloc流程：
1. 将用户申请的大小加上元数据开销，得到真正需要分配的内存大小；这意味着实际分配的内存块会比用户请求的大小更大，以包含**内存分配器的元数据**，比如大小、状态等信息。
2. 查找bins，选择合适的内存块进行分配
   
#### malloc相关系统调用
1. brk()：将break指针直接设置为某个地址
2. sbrk()：将break指针从当前位置移动increment所指定的增量。
3. mmap()：当申请小内存的时，malloc使用sbrk分配内存；当申请大内存时，使用mmap函数在内存映射区申请内存；默认临界点是128KB。


#### free
1. 根据用户传入的 ptr，计算出其对应 chunk 的起始地址（ptr减去元数据大小）
2. 选择释放到哪个bins。

### new/delete和malloc/free的区别
1. 语义层面：new/delete是C++的运算符，具有构造和析构对象的能力；malloc/free是C语言的函数，仅负责内存分配和释放，不涉及对象生命周期管理。
2. 性能层面：new/delete通常会调用malloc/free进行内存管理，但它们还会执行额外的构造/析构操作，因此在某些情况下可能比malloc/free稍慢。
3. 错误处理：new在分配失败时会抛出std::bad_alloc异常；malloc在分配失败时返回NULL。

### 继续深挖
#### new分配内存失败会报什么异常？
new在分配内存失败时会抛出**std::bad_alloc**异常。这个异常是std::exception的一个派生类，表示内存分配失败的错误。当使用new运算符分配内存时，如果系统无法满足分配请求（例如内存不足），new会自动抛出std::bad_alloc异常，程序可以通过捕获这个异常来处理内存分配失败的情况。

### new一定会抛出异常吗？
默认情况下，new运算符在分配内存失败时会抛出std::bad_alloc异常。然而，C++还提供了一种不抛出异常的new版本，称为**nothrow new**。使用nothrow new时，如果内存分配失败，它会返回一个空指针（nullptr）而不是抛出异常。

### 什么情况会导致new分配内存失败
new失败的本质是申请不到足够且可用的地址空间，常见原因包括：
1. 进程虚拟内存耗尽：在32位进程中常见，当申请的内存总量超过了进程可用的虚拟地址空间时，new会失败。
2. 物理内存与交换空间不足：当系统的物理内存和交换空间都无法满足分配请求时，new也会失败。
3. 分配器自身限制：某些平台或环境可能对单次分配的内存大小有限制，如果申请的内存块超过了这个限制，new也会失败。
4. 内存碎片化严重：当堆内存中存在大量小的空闲块，无法满足较大内存块的连续分配请求时，new可能会失败。
5. 系统资源限制：操作系统可能对每个进程的内存使用设置了限制，如果申请的内存超过了这个限制，new也会失败。

### new/delete 和 malloc/free 混用的问题
new/delete和malloc/free混用会导致严重的内存管理问题，因为它们使用不同的内存分配机制和管理策略。具体问题包括：
1. 内存泄漏：如果使用new分配内存但使用free释放，free无法正确处理new分配的内存块，导致内存泄漏。
2. 未定义行为：混用可能导致程序崩溃或产生不可预测的行为，因为free可能会尝试释放一个由new分配的内存块，而这个内存块的元数据格式与malloc不同，C++会在new分配的内存的元数据中添加对象语义层,例如new[]会在元数据中添加数组长度、对齐信息等。（new/delete使用C++的内存分配器，而malloc/free使用C的内存分配器，它们在管理内存块的元数据和内部结构上存在差异，混用会导致内存管理器无法正确识别和处理内存块，从而引发未定义行为）
3. 资源管理混乱：混用会使得内存管理变得混乱，难以追踪和调试内存问题，增加了程序的复杂性和维护难度。因此，建议在同一程序中始终使用new/delete或malloc/free来管理内存，以确保内存管理的一致性和安全性。

### 怎么模拟内存分配失败的情况来测试new的异常处理机制？
可以通过以下几种方法来模拟内存分配失败的情况，以测试new的异常处理机制：
1. **限制可用内存**：在操作系统层面限制程序的可用内存，例如在Linux系统中使用`ulimit -v`命令限制进程的虚拟内存大小，或者在Windows系统中使用工具如Process Explorer来设置内存限制。
2. **使用nothrow new**：在代码中使用nothrow new来模拟内存分配失败的情况，例如：
   ```cpp
   #include <new>
   #include <iostream>

   int main() {
       // 模拟内存分配失败
       std::nothrow_t nothrow;
       int* ptr = new (nothrow) int[1000000000]; // 申请一个非常大的数组，可能会失败

       if (ptr == nullptr) {
           std::cout << "内存分配失败，ptr为nullptr" << std::endl;
       } else {
           std::cout << "内存分配成功" << std::endl;
           delete[] ptr; // 记得释放内存
       }

       return 0;
   }
   ```
3. **模拟分配失败的函数**：可以编写一个自定义的内存分配函数，模拟内存分配失败的情况，例如：
   ```cpp
   #include <new>
   #include <iostream>

   void* operator new(std::size_t size) {
       // 模拟内存分配失败
       throw std::bad_alloc();
   }

   int main() {
       try {
           int* ptr = new int; // 这将抛出std::bad_alloc异常
       } catch (const std::bad_alloc& e) {
           std::cout << "捕获到内存分配失败的异常: " << e.what() << std::endl;
       }

       return 0;
   }
   ```
