## malloc分配内存失败的处理措施

在 C/C++ 中，使用 `malloc` 申请内存时，如果系统内存不足或分配过大，`malloc` 会分配失败并返回一个空指针（`NULL` 或 `nullptr`）。这与 C++ 中 `new` 操作符默认抛出 `std::bad_alloc` 异常的行为不同。

如果不加检查继续解引用该空指针，会导致程序立刻崩溃（段错误 Segmentation Fault）。因此，必须进行后续处理。常见的处理措施如下：

### 1. 立即检查返回值
这是最基础的原则。每次调用 `malloc`（以及 `calloc`、`realloc`）后，都必须检查返回值是否为空。
```cpp
int* ptr = (int*)malloc(100 * sizeof(int));
if (ptr == nullptr) {
    // 处理分配失败的情况
}
```

### 2. 错误记录与排查
检测到分配失败时，应该记录日志信息或把错误输出到标准错误流（`stderr`），可以结合系统错误码 `errno` 打印详细原因，方便日后排查。
```cpp
#include <iostream>
#include <cstring>

if (ptr == nullptr) {
    std::cerr << "Memory allocation failed: " << strerror(errno) << std::endl;
}
```

### 3. 释放已占据的资源 (防止内存泄漏)
如果是执行组合任务中途发生的某种结构体/数组分配失败，必须在返回前将其之前已经成功分配的资源全部 `free` 掉，或者关闭已经打开的文件句柄，避免资源泄漏。然后可以返回错误码给调用者。

### 4. 抛出异常 (封装为 C++ 风格)
虽然 `malloc` 本身不抛异常，但如果在 C++ 项目中必须用到 `malloc`（比如涉及与 C 语言的遗留库交互），可以手动将 `nullptr` 的情况转换为抛出异常，交给上层业务处理。
```cpp
int* ptr = (int*)malloc(100 * sizeof(int));
if (ptr == nullptr) {
    throw std::bad_alloc(); 
}
```

### 5. 终止进程 (严重失败时的兜底策略)
如果这段内存是整个应用或系统核心运行必备的（例如服务器启动时的全局配置表），失败意味着程序无法继续提供任何服务，此时可以在日志记录后直接调用 `exit(EXIT_FAILURE)` 或 `abort()` 安全退出程序。

> **C++ 开发的最佳实践**：
> 除非需要和 C 库接口兼容或者定制底层内存池，在 C++ 开发中应该始终优先考虑使用 `new` / `delete`，甚至是**智能指针和 STL 容器**。`new` 默认在分配失败时抛出 `std::bad_alloc`，可以配合 `try-catch` 捕获，从而避免遗漏 `nullptr` 检查而导致的崩溃危险。
