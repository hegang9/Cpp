## new和delete的底层工作原理

在 C++ 中，`new` 和 `delete` 不仅仅是分配和释放内存的函数，它们是**表达式（Expression）**。对于非内置类型的对象，它们的执行过程严格分为“内存管理”和“对象生命周期管理”两个阶段。

### 1. `new` 运算符的底层步骤
当执行类似 `T* ptr = new T(args);` 的代码时，编译器实际会按照以下顺序生成代码逻辑：

1. **内存分配（调用 `operator new`）**：
   - 首先调用底层且全局（或类重载）的库函数 `void* operator new(size_t size)` 来分配能够容纳一个 `T` 类型对象的原始、未初始化内存。
   - **底层实现**：`operator new` 内部通常是一个死循环，不断调用 C 语言的 `malloc()`。
   - **失败处理机制（new_handler）**：如果 `malloc` 失败返回 `NULL`，它会检查是否设置了 `new_handler`（用户通过 `std::set_new_handler` 注册的内存不足处理回调函数）。如果设置了，就调用该处理函数尝试释放其他被锁定的或可复用的内存；如果没有设置或者经过各种尝试依然无法分配出内存，则抛出 `std::bad_alloc` 异常。

2. **对象构造（调用构造函数）**：
   - 在第一步分配出来的原始内存之上，编译器会使用类似**定位分配（Placement new, `new(ptr) T;`）**的方式，在这块确定的内存地址上调用对象 `T` 的构造函数 `T::T(args)`。
   - **异常安全保证**：这是极其重要的一环。如果在调用构造函数期间抛出了任何异常，由于此时 `new` 表达式尚未完成并返回指针，用户代码将无法捕获指针并释放内存。因此编译器会**自动拦截该异常**，并调用对应的 `operator delete` 把第一步申请的内存释放掉，以**保证不会发生内存泄漏**，然后再将原异常向外继续抛出。

### 2. `delete` 运算符的底层步骤
当执行类似 `delete ptr;` 的代码时，底层的执行流程如下：

1. **安全检查**：
   - 首先检查 `ptr` 是否为 `nullptr`。如果是空指针，`delete` 会直接打断后续步骤，不执行任何操作。这解释了**为什么对空指针执行 `delete` 总是安全且无副作用的**。

2. **对象析构（调用析构函数）**：
   - 编译器通过指针 `ptr` 显式回调该对象的析构函数 `ptr->~T()`。
   - 这一步的作用是销毁对象的内部状态，将对象内部管理的引用资源（比如对象内部 `new` 出的其他堆内存、打开的文件句柄、网络套接字等）进行彻底清理。
   - **注意**：C++ 强烈要求析构函数不能抛出异常。如果析构函数中抛出异常并未在内部捕获，一旦遇到其它异常正在进行栈展开的过程，会导致整个程序触发 `std::terminate` 直接崩溃。

3. **内存释放（调用 `operator delete`）**：
   - 在对象的资源被清理得干干净净并且死亡之后，编译器会调用标准库函数 `void operator delete(void* ptr)`。
   - **底层实现**：将这整块占用的底层内存块交还回操作系统或者用户层分配器。它通常在内部调用 C 语言的 `free()`。

### 3. 数组分配 `new[]` 和 `delete[]` 的底层差异与陷阱
使用 `new[]` 和 `delete[]` 来创建及销毁对象数组时，编译器必须知道数组中包含了多少个对象，以便执行相应数量的析构过程。

- **`new[]` 分配过程**：
  - 它调用 `operator new[]`。当为自定义类型（含有非平凡析构函数）分配数组时，编译器通常会额外多申请一小块内存（通常位于返回指针之前的 4 或 8 字节），称为 **Cookie（或者 Array Size Header）**，用来记录数组的元素个数。随后在这个连续的内存空间上按照正序（`0` 到 `N-1`）循环调用每个元素的默认构造函数。
- **`delete[]` 释放过程**：
  - 当调用 `delete[] ptr;` 时，编译器会自动将指针往前偏移去读取那个隐式保存的**元素个数 `N`**。
  - 接着按照**逆序**（`N-1` 递减到 `0`）对每一个数组元素调用析构函数。
  - 最后调用 `operator delete[]`（实质也是 `free`），不仅释放对象占用的内存，也连同头部 Cookie 占用的内存一并归还给堆区。
- **巨大的 UB 陷阱**：
  - 如果对一个通过 `new[]` 分配出来的非内置类型数组使用了单独的 `delete` 而不是 `delete[]`，不仅只有第 1 个元素的析构会被调用（导致其余元素内部资源泄漏），并且传递给底层的 `operator delete` (或者 `free`) 的首地址指针由于缺少了对头部的修正偏移，往往会导致严重的堆内存控制块损坏，在运行时引爆 `Segmentation fault` 崩溃。
